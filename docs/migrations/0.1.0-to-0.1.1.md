# Migration: 0.1.0 → 0.1.1

Version 0.1.1 makes the Better Research **builder and repository scaffolding English-first for global portability** while keeping the language of research outputs configurable per project.

This is primarily a documentation/scaffolding migration. It does **not** require translating empirical research content, source quotations, field materials, participant materials, or manuscripts unless the project itself requires that change.

## Why this migration exists

Version 0.1.0 still contained Indonesian instructions, headings, placeholders, and quality-gate tokens across skills, templates, project files, and examples. That limited portability across institutions, countries, and AI environments.

Version 0.1.1 standardizes the builder language to English.

## Canonical token changes

Version 0.1.1 replaces the legacy non-English scaffolding/status vocabulary with these canonical English tokens:

- `NOT YET FILLED`
- `NOT YET DECIDED`
- `NOT YET VERIFIED`
- `NOT ASSESSED`
- `REVISION REQUIRED`
- `READY`
- `NOT APPLICABLE`
- `NOT YET SYNCED`

Do not rewrite historical Git commits. Update only active project scaffolding and records that still rely on the legacy operational vocabulary.

## Language-policy change

The builder now follows two separate rules:

1. **Repository documentation language:** English.
2. **Research-output language:** project-specific.

A research project may remain Indonesian, English, bilingual, or multilingual. Record the language decision in `research/project-brief.md`.

## Recommended migration steps

Create a migration Issue in the RESEARCH repository and:

1. update builder version from 0.1.0 to 0.1.1;
2. update active copies of `AGENTS.md`, skills, workflow docs, and templates only where the project has not intentionally customized them;
3. translate active operational labels/status tokens to the new English canonical tokens;
4. preserve empirical content and quotations in their research language;
5. add or verify the project language policy in the project brief;
6. update automation/bootstrap scripts if the project copied them;
7. run `python scripts/validate_repository.py`;
8. review the diff to ensure no research meaning changed during translation;
9. merge through the project’s normal Issue/PR workflow.

## Do not do this automatically

Do not mass-translate:

- participant quotations;
- interview transcripts;
- field notes;
- source quotations;
- already approved instruments;
- empirical manuscripts whose language is intentionally not English.

Those artifacts follow the project language policy, ethics requirements, and translation protocol—not the builder documentation language.

## Gate impact

This migration does not automatically reopen academic gates.

Reopen a gate only if the migration changes the **meaning** of a substantive research statement, criterion, method, or interpretation. Pure translation of builder scaffolding is a delivery/configuration change, not new academic evidence.

## Completion

Migration is complete when:

- `research/project-brief.md` records Builder version: 0.1.1;
- active builder instructions and templates use English operational vocabulary;
- project output-language requirements are explicitly recorded;
- repository integrity checks pass;
- no substantive research claim changed unintentionally;
- the migration PR is merged and verified.
